# Отчёт о выполнении orders-aggregator

## Результат

Выполнены скидки в дневной статистике и исправление расчёта календарных дней. Дополнительно создан React-интерфейс с двумя страницами, диагностикой, Redux slices, TanStack Query, React Router, FSD и shadcn/ui. Сервер и React расположены в соседних backend/ и frontend/. В корне находятся Compose, документация и общий пакет команд. Docker-окружение запускается одной командой npm run up.

Таблица проверки скидки вынесена на страницу логов. Основная таблица заказов показывает сумму до скидки, скидку в рублях и процент, сумму после скидки и кнопку суммы клиента.

## Что исправлено

| Область | До | После |
| --- | --- | --- |
| Скидки | Новые поля внешнего API отбрасывались | Сохраняются процент и фактическая оплата, отчёт возвращает gross/net/discount/total |
| День заказа | Одно текущее смещение применялось к историческим датам | Смещение определяется на момент каждого createdAt |
| Копейки | Math.floor(rub * 100) мог терять копейку | Десятичное преобразование через BigInt |
| Конкуренция версий | Отдельные SELECT и безусловный upsert допускали гонку | Условие версии проверяется в одном SQL upsert |
| Ранее загруженные данные | Те же updatedAt мешали получить новые поля | Одноразовое обогащение через pricing_version |
| Частичный сбой sync | Кэш React мог скрыть уже сохранённые записи | Инвалидация выполняется в onSettled с сохранением ошибки |

## Что видно в интерфейсе

- Заказы — загрузка, статусы, суммы, даты, выбор 10/20/50/100 записей на страницу, общее количество, первая/последняя страницы и окно расчёта клиента.
- Окно клиента — выбор дат, gross, discount, net и таблица всех учтённых заказов с собственной серверной пагинацией; общие суммы и количество относятся ко всему периоду.
- Логи — период проверки клиентов, счётчики, таблица ошибок скидки и таблица проверки клиентов.
- Прежний алгоритм показан отдельными строками. Текущие ошибки и историческое сравнение различаются.
- Старые и неполные денежные данные показаны отдельными счётчиками.
- Все таблицы используют TanStack Table v8. API возвращает total и метаданные страниц, списки логов имеют независимые страницы.
- Для загрузки добавлены skeleton, spinners и сохранение прежних данных при обновлении. Ошибка без данных не выдаётся за пустой успешный ответ.
- Окно открывается за 200 мс и закрывается за 130 мс; reduced motion отключает движение. Исправлено переполнение на узком экране.

## Решения и ограничения

Фактическая оплата из API используется для net, даже если математическая проверка выявит расхождение. Отдельного отчёта платёжной системы нет, поэтому проверяется согласованность данных.

Заказы без обоих новых полей считаются старым форматом без скидки. При отсутствии amountPaid и наличии процента применяется расчётный fallback, помеченный как неполные данные. Округление процентного расчёта принято к ближайшей копейке, половина вверх. Эти допущения зафиксированы в SOLUTION.md.

У исходных зависимостей бэкенда npm audit сообщает 7 уязвимостей, включая 2 high и 2 critical; production-установка сообщает 2 high. Их обновление вынесено в следующий этап. Фронтенд установлен с нулём найденных уязвимостей.

Для запуска на другом компьютере нужен приложенный к заданию архив внешнего образа либо уже загруженный orders-mock:3. Учётные данные и открытые порты Compose предназначены для локального тестового окружения.

Сохранены ограничения createContainer(db, api) и OrdersApi. TASK.md не редактировался.

+## Что реализовано
+
+Добавлены сохранение `discountPercent` и `amountPaid`, миграция `002_order_pricing.sql` и расширенный дневной ответ `date, total, gross, discount, net`. `total` равен `gross`. В статистике участвуют только заказы со статусом `paid`.
+
+Синхронизация и вебхуки используют один нормализатор. Суммы сохраняются в целых копейках. `amountPaid` является приоритетным источником фактической оплаты. Несовпадение с процентом фиксируется диагностикой, переданная оплата сохраняется.
+
+Применение версии перенесено в атомарный PostgreSQL upsert. Более старая версия не перезаписывает свежую при одновременных запросах. Повторные события возвращают `stale`.
+
+Миграция помечает ранее сохранённые записи `pricing_version = 0`. Повторный sync один раз догружает данные скидки даже при совпадающем `updatedAt`, затем обычные повторы снова пропускаются. Это также позволяет исправить прежнюю конвертацию сумм у старых записей.
+
+Сигнатура `createContainer(db, api)` и интерфейс `OrdersApi` совместимы с исходным контрактом.

+## Причина мартовского расхождения
+
+Исходный код один раз вычислял смещение таймзоны клиента на текущую дату запуска сервера и применял его ко всем историческим заказам. Для `Europe/Berlin` это неверно на переходе к летнему времени 29 марта 2026 года.
+
+Теперь смещение вычисляется для каждого `order.createdAt`. Выборка имеет запас по UTC-границам, после чего заказ попадает в календарный день клиента. Нулевые дни и включительные границы периода сохранены.
+
+Причину проверили тремя способами.
+
+1. Регрессионный тест с заказами на границах суток и переходе времени.
+2. Один и тот же мартовский отчёт проверен при системной дате в январе и июле.
+3. PostgreSQL независимо группирует тот же снимок заказов через `AT TIME ZONE` и сверяет все поля дневного ответа.
+
+На финальном снимке после вебхуков прежний алгоритм и правильный расчёт для `c_7` различаются так.
+
+| Дата | Прежний total на том же снимке | Исправленный gross |
+| --- | ---: | ---: |
+| 2026-03-29 | 43964 | 34658 |
+| 2026-03-30 | 52201 | 59684 |
+| 2026-03-31 | 44064 | 35401 |

+После исправления все 40 клиентов совпали с независимым пересчётом за выбранный период. Ещё два отличия прежнего алгоритма проявились у клиента `c_23` с `America/New_York`.

+## Дополнительная ошибка денежных сумм
+
+`Math.floor(rub * 100)` терял копейку из-за двоичного представления дробей. Например, `19.99 * 100` даёт `1998.9999999999998`, после floor получалось `1998`.
+
+Перевод теперь выполняется через десятичное представление и BigInt. Он поддерживает числовые строки и экспоненциальную запись, отбрасывает настоящие доли копейки согласно исходному контракту и отклоняет переполнение безопасного целого.
+
+Это отдельный дефект, важный для новой статистики оплаты. Исходная жалоба по дневным суммам до скидок воспроизводится ошибкой часового пояса.

+## Допущения

+- Если оба новых поля отсутствуют, заказ считается старым форматом без скидки. В живом API найдено 1177 таких заказов.

+import { useState } from "react";
+import { useQuery } from "@tanstack/react-query";
+import { customerReportQuery } from "@/entities/customer";
+
+export function useCustomerReport(customerId: string, active: boolean) {
+  const [period, setPeriod] = useState<{ from: string; to: string } | null>(null);
+  const [pagination, setPagination] = useState({ pageIndex: 0, pageSize: 20 });
+  const query = useQuery({ ...customerReportQuery(customerId, period?.from ?? "", period?.to ?? "", pagination),
+    enabled: active && period !== null,
+  });
+  return { query, pagination, setPagination, period,
+    reset: () => setPeriod(null),
+    calculate: (from: string, to: string) => {
+      if (period?.from === from && period.to === to && pagination.pageIndex === 0) { void query.refetch(); return; }
+      setPagination((current) => ({ ...current, pageIndex: 0 })); setPeriod({ from, to });
+    },
+  };

+import { LoadingIndicator, Skeleton } from "./loading-indicator";
+import { Table, TableBody, TableCaption, TableCell, TableHead, TableHeader, TableRow } from "./table";
+
+interface Props<T> {
+  data: T[]; columns: ColumnDef<T>[]; total: number; pagination: PaginationState;
+  onPaginationChange: (value: PaginationState) => void; label: string; empty: string;
+  loading?: boolean; refreshing?: boolean; caption?: string; compact?: boolean;
+}
+export function DataTable<T>({ data, columns, total, pagination, onPaginationChange, label, empty,
+  loading = false, refreshing = false, caption, compact = false }: Props<T>) {
+  const busy = loading || refreshing;
+  const table = useReactTable({ data, columns, getCoreRowModel: getCoreRowModel(), manualPagination: true,
+    rowCount: total, state: { pagination }, onPaginationChange: (next) =>
+      onPaginationChange(typeof next === "function" ? next(pagination) : next),
+  });
+  useEffect(() => {
+    if (busy) return;
+    const last = Math.max(0, Math.ceil(total / pagination.pageSize) - 1);
+    if (pagination.pageIndex > last) onPaginationChange({ ...pagination, pageIndex: last });
+  }, [total, pagination, onPaginationChange, busy]);
+  return <section aria-label={label} aria-busy={busy}>
+    <div className="flex min-h-8 items-center pb-2" aria-live="polite">
+      {busy && <LoadingIndicator>{loading ? "Загружаем таблицу…" : "Обновляем таблицу…"}</LoadingIndicator>}

+      tabIndex={0} role="region" aria-label={label + ": прокрутка"}>
+      <Table>
+        {caption && <TableCaption className="m-0 p-3 text-left whitespace-normal">{caption}</TableCaption>}
+        <TableHeader>{table.getHeaderGroups().map((group) => <TableRow key={group.id}>
+          {group.headers.map((header) => <TableHead key={header.id}>{flexRender(header.column.columnDef.header, header.getContext())}</TableHead>)}
+        </TableRow>)}</TableHeader>

+            {columns.map((_, cell) => <TableCell key={cell} className="h-14"><Skeleton className="h-4 min-w-16" /></TableCell>)}
+          </TableRow>) : table.getRowModel().rows.map((row) => <TableRow key={row.id}>
+            {row.getVisibleCells().map((cell) => <TableCell key={cell.id}>{flexRender(cell.column.columnDef.cell, cell.getContext())}</TableCell>)}
+          </TableRow>)}
+          {!loading && !data.length && <TableRow><TableCell colSpan={columns.length} className="py-10 text-center text-muted-foreground whitespace-normal">{empty}</TableCell></TableRow>}
